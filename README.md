# Сайт ЛДЦ "Гален"

Сайт клиники: запись на приём онлайн, кабинеты клиента, врача и администратора.
Фреймворков и зависимостей нет. Данные хранятся в localStorage браузера, серверной части нет.

## Запуск

- Разработка: откройте index.html в браузере. Стили и скрипты подключаются напрямую из папок css/ и js/.
  Если браузер блокирует локальные файлы, запустите в папке проекта: python3 -m http.server
- Сборка: npm run build. Результат: dist/galen-clinic.html, один файл, его можно выкладывать на хостинг.
- Тесты: npm test.

Node.js нужен только для сборки и тестов. Устанавливать npm-пакеты не требуется.

## Структура проекта

- index.html: разметка страницы и порядок подключения файлов
- build.js: сборка проекта в один HTML-файл
- css/: стили по разделам, порядок подключения важен
- js/config.js: ключи localStorage, метка сборки, генератор id
- js/data/: начальные данные и работа с хранилищем (seed.js, icons.js, resources.js, schedule.js, db.js)
- js/auth/: сессия и текущий пользователь (session.js), окна входа и регистрации (auth.js)
- js/router.js: навигация и отрисовка страниц
- js/ui/: уведомления, меню, шапка, модальные окна, карусели, правка текстов
- js/views/: по одному файлу на раздел сайта (главная, каталог, врачи, запись, для пациента, кабинеты, админка)
- js/helpers.js: мелкие общие функции
- js/main.js: запуск, подключается последним
- tests/: тесты и эталон для сравнения

## Как устроен код

- Все файлы в js/ это обычные скрипты с общей глобальной областью видимости, а не ES-модули.
  Причина: в разметке используются обработчики вида onclick="функция()".
  Порядок подключения задаётся в index.html, сборка берёт его оттуда же.
- Состояние хранится в трёх глобальных объектах: DB (данные), SESSION (кто вошёл), ROUTE (текущая страница).
  Состояние интерфейса (открытая вкладка, шаги записи) лежит в переменных рядом с соответствующим экраном.
- Отрисовка: go(view, params) выставляет ROUTE и вызывает render(). Функция render() вызывает нужную функцию
  вида viewИмя(), которая возвращает строку HTML, и подставляет её на страницу. Перерисовка всегда полная.
- Изменение данных везде делается одинаково: изменить DB, вызвать saveDB(), затем render() и при желании toast().
  Образец: функция addService в js/views/admin.js.
- Роли: currentUser().role равен admin, doctor или client. У врача в данных есть собственное поле role
  (должность), поэтому currentUser() отдаёт её под именем jobTitle.

## Модель данных (объект DB)

- categories: направления. Поля: id, name, short, icon, image (необязательное).
- services: услуги по направлениям, словарь вида id направления: список. Элемент списка:
  услуга (id, name, price) или заголовок группы (group: true, label).
- doctors: врачи. Поля: id, name, role (должность), specialties (список id направлений),
  serviceIds (список id услуг, которые врач оказывает), experience, education, photo, workSchedule.
- workSchedule: график врача по ключам sun, mon, tue, wed, thu, fri, sat.
  Значение: {start: "09:00", end: "18:00"} или null для выходного.
- doctorLogins: словарь вида хеш пароля: id врача.
- doctorBlocks: время, занятое врачом (отпуск, дела). Поля: id, doctorId, start, end.
- users: клиенты. Поля: id, name, phone, email, passwordHash, linked.
- appointments: записи. Поля: id, userId, doctorId, serviceName, price, catId, date, time, status.
- texts: тексты главной страницы, которые администратор правит прямо на странице.

Врач связан с направлением через specialties, а с конкретной услугой через serviceIds.
Свободные слоты считает функция slotsForDay в js/views/booking.js с учётом графика, блокировок и чужих записей.

## Типовые задачи

- Новый экран: добавить функцию viewИмя() в js/views/, строку с ней в render() (js/router.js),
  переходить на него через go("имя", параметры).
- Новое поле у врача: добавить в js/data/seed.js и в addDoctor (js/views/admin.js), добавить поле в форму админки
  и миграцию в loadDB (js/data/db.js).
- Изменение формата данных: только вместе с миграцией в loadDB, потому что у пользователей уже сохранён старый формат.
  Примеры миграций там же.
- Цвета и тема: переменные лежат в css/base.css, тёмная тема переопределяет их в css/theme-dark.css.
  Для текста фирменного цвета на карточках используйте var(--accent): он светлеет в тёмной теме.

## Тесты

- tests/flows.js: сценарии. Вход администратора и врача, регистрация, запись, правки услуг и направлений,
  миграция старых данных.
- tests/check.js: снимок HTML 93 экранов (4 роли, все страницы и вкладки) сравнивается с tests/baseline.json.
  Это ловит любое непреднамеренное изменение вёрстки. Если вы меняли интерфейс намеренно, выполните
  npm run test:update и просмотрите изменения эталона.
- Тесты запускаются в Node без браузера, DOM имитируется (tests/harness.js). Поэтому стили, анимации и жесты
  тестами не покрыты, их нужно проверять в браузере.

## Известные ограничения

1. Нет сервера. Данные лежат в localStorage конкретного браузера, поэтому администратор и врач на разных
   устройствах не видят данные друг друга. Для реального запуска нужен бэкенд. Точки замены: loadDB, saveDB
   и функции add, update, remove, toggle в js/views/admin.js.
2. Пароль администратора проверяется на клиенте по хешу, который лежит в коде (adminPasswordHash в defaultDB).
   Это не защита. Пароли врачей и клиентов хешируются SHA-256 без соли, этого достаточно только для прототипа.
3. Вход через Госуслуги, VK, MAX и код подтверждения на почту реализованы как заглушки
   (mockSocialAuth, startPasswordReset).
4. Данные из полей (имена врачей, названия услуг) вставляются в HTML без экранирования. Перед использованием
   с реальными пользователями нужно добавить функцию экранирования.
5. Глобальное состояние и полная перерисовка страницы подходят для текущего объёма. При росте проекта
   имеет смысл перейти на ES-модули и выделить единый объект состояния.
6. Часть занятых слотов у врачей имитируется (функция seededTaken), это демонстрационная логика.
